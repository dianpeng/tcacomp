# Loop Tiling

- This is a very large optimization pass
  - [1] Decide placement of SMEM/FRAG cache statically
  - [2] Decide parallisation placehoment/assignment
  - [3] Problem formulation and searching solution
  - [4] MemLoad cache mark and Loop tiling rewrite
    - Ie rewrite the IR into loop tiling style loops

## Candidative Object

- Loop tiling works on **loop nest tree**
  - Using internal/analysis/loopforest to obtain all loop nest trees for a specific ir GRAPH
    - Ie all loop nest trees in a single kernel program

  - Denote each loop nest tree as LNT

- Loop tiling mapping
  - Before the loop tiling pass, each loop nest tree will have its own original loops
    - Ie each loop nests are presented by a chain of Iter node
  - Each Iter node will have its corresponding tiling loop
    - Static rewrite strategy, 1:1 mapping

```

// Before tiling rewrite

for (auto i = 0; i < I; i++) {
  for (auto j = 0; j < J; j++) {
  }
}

// After tiling rewrite

// [1] tile outside loop
//     tile-id enumeration: the between loops count TILES, one iteration per tile,
//     each tile's base offset is tile_id * tile_size
for (auto i = 0; i < ceil(I/i_tile_size); i++) {
  for (auto j = 0; j < ceil(J/j_tile_size); j++) {
    // [2] tile inside loop

    const auto i_offset = i * i_tile_size;
    const auto j_offset = j * j_tile_size;

    // the following materialized tile size for tile loop will save branch and have
    // much better generated code structure.
    const auto max_tile_size_i = min(i_tile_size, I - i_offset);
    const auto max_tile_size_j = min(j_tile_size, J - j_offset);

    for (auto tile_i = 0; tile_i < max_tile_size_i; tile_i++) {
      for (auto tile_j = 0; tile_j < max_tile_size_j; tile_j++) {
        ....
      }
    }

  }
}

## Parallisation Assignment, Loop Tiling, and Search Solution

- Assign each LNT's loop layer with a parallisation strategy

- Parallisation Strategy
  - Our parallisation strategy is directly modeling CUDA's threading design
  - Following property is called **space of concurrency**/SoC
    - It represents a way to assign a CUDA style parallisation to a specific iteration
  - (1) CTA
  - (2)/(3) Warp/Thread
  - (4) sequential, by default it is sequential loop

  - A LNT must be assigned sequentially from (1) -> (2)/(3)
    - An assignment is feasiable when it at least has one CTA assignment
  - For now (2)/(3) are the same, we ALWAYS assign on granularity of WARP
    - ie consequtive 32 threads atomically

- Cuda Parallisation Normalization
  - Cuda code has its own coorindates mapping, blockIdx.(x/y/z) and threadIdx.(x/y/z)
  - We will use our own normalized method
    - Which allow us to remap CTA and thread specifically for different LNT
  - All our launched kernel will have normalized grid and block dim
    - (1) one gridDim.x indicate total # of input CTAs
    - (2) one blockDim.x indicate total # of threads per CTA
      - Each CTA's # of threads MUST BE multipler of WARP, ie 32
    - Notes: since we will remap everything anyway, so using the simplest kernel launch is fine

- Runtime Object Support Arbitary Remapping
  - Runtime allows **arbitary fine grained slice for different spaces of concurrency**
    - For all spaces of concurrency, we allow multi-dimension style mapping
      - NOT only x/y/z as normal cuda kernel
  - The map objects are PER-LNT scoped ordinary C++ template objects
    - Constructed at the very start of the loop nests generated for that LNT
    - Lifetime is that LNT's scope: once the LNT is done its maps are gone, the
      next LNT constructs its own remap
    - This per-LNT remapping is exactly WHY different mappings of the provided
      totals are needed
  - The optimization pass guarantees every LNT obeys the SAME constraint bounds
    and all LNT schedules combined stay under the total upper bounds

- Assignment SMEM/FRAG cache
  - The assignemnt of SMEM/FRAG is as following 2 layers
    - 1) Decide which sets of iterations to participate in SMEM cache
    - 2) Decide # of cache size
    - For 2), it is decided implicitly by tile size, not controled by this pass
  - This small pass is responsible for
    - Deciding sets of iterations to own/reuse the cache

  - Cache Tie Semantics
    - The author's rules, stated normatively
      - RULE 1, TIE: a cache site is TIED to a specific Iteration of the LNT
        - The tie IS the placement: the MemLoad is hoisted to sit DIRECTLY ABOVE the
          tied iteration's loop
      - RULE 2, WHOLE DIMENSION LOAD: moving a MemLoad UP past an iteration LOSES
        that iteration's dimension, ie the cache loads that WHOLE dimension
        - Hoisting past an iteration that indexes the load, ie is in its INS, the
          cache loads that whole dimension into SMEM at fixed enclosing indices
        - Hoisting past an iteration NOT in the load's INS is free, footprint unchanged
      - RULE 3, TILING DEMOTION: tiling automatically demotes the cache from full
        dimension to a tile of that dimension
        - At tie time the coverage is the FULL dimension, when loop tiling applies,
          each covered dimension is automatically demoted from full extent to that
          dimension's tile_size
        - The tile size IS the cache size knob, consistent with cache size being
          decided implicitly by tile size
    - TWO distinct levels, do NOT fuse them
      - SET level, MemLoad Overlap Analysis: the innermost REFERENCED Iter
        - Sets group CO-TRAVERSED loads, ie loads sharing their innermost referenced
          dimension
        - This level is candidate grouping + admission filtering only, it is where
          the set-size >= 2 filter lives
      - TIE level, per load: the innermost NON-referenced Iter, ie the operational
        tie rule below
        - This level is the actual cache placement, whole-dimension coverage and
          tiling demotion per RULE 1/2/3
      - Reuse lives ABOVE the set level: the set's co-traversed loads get their
        caches TIED ABOVE the set level, so the shared innermost sweep, ie the
        k-sweep, turns into SMEM hits that survive the enclosing sweeps

    - Derived from the rules
      - Reuse accrues across the tied iteration's sweep and everything inner to it,
        the cache re-loads once per enclosing iteration
        - Placement trades covered footprint, product of covered extents, against
          reload frequency
      - Operational tie rule: tie(p) = the innermost Iter of the LNT that is NOT in
        INS(p)
        - All INS members end up at-or-inside the tie, outer INS members are fixed
          scalar selections for the whole-dim load
        - Equivalently, scan the LNT inner -> outer and stop at the first level NOT
          referenced by the load
      - Loads whose INS spans the ENTIRE LNT tie above the outermost loop, ie
        whole-tensor coverage demoted to tiles by RULE 3, allowed, NOT excluded
      - Worked check, the matmul below, walks BOTH levels
        - SET level: lhs[m][k] INS = {iterM, iterK} and rhs[n][k] INS = {iterN, iterK}
          share iterK as innermost referenced -> one set {lhs, rhs} @ iterK, which
          passes the >= 2 set filter
        - TIE level, the placements: lhs tie -> iterN
          - Covers [ · ][K] whole, reloaded per m, reused across n and k
        - rhs tie -> iterM, above the outermost loop
          - Covers [N][K] whole, ie the "cover [n][k] 2 dimensions" case
        - Ie the set admits the co-traversed pair AT iterK, then each load's cache
          is tied ABOVE: the whole-dim caches at the ties are what turn k-sweep
          loads into SMEM hits and survive the enclosing sweeps
        - Promotion OUTCOME at default shapes (ruled 2026-10-21): lhs is
          promoted as a 128 B per-thread FRAG (reuse = its n-walk = 32);
          rhs's [N][K] SMEM window — 256 threads x 32 x 32 x 4 B = 1 MB —
          exceeds the 64 KB kernel-wide budget and is DECLINED by the
          fallback. Intentional; see loop_tile_lower.md §6bis PHASE 4

  - MemLoad Overlap Analysis
    - A small **analysis** pass to decide a set of candidative cache insertion point related to iteration
      - **DO NOT put it into internal/analysis**, this is local analysis which will only be relevant to this optimization

    - (1) For a specific LNT, collect all MemLoad that has subscript reference to one of the iteration for this LNT
    - (2) For all such MemLoad node form a set, denoted as I
      - Initially each element forms its own **set** in I
    - (3) Perform a union algorithm within the set I
      - 0) Subroutine findINS: For MemLoad p
        - find **all its subscript used Iter node**, denoted iter node set/INS
        - Setup an empty set for result
        - Foreach subscript operand in MemLoad
        - Chasing the Input list until hit **all InductionVariable**
        - Add the Iter node InductionVariable pointed to into this Set
          - Equality of Iter is defined by ValueEqual, just like GVN
      - 1] For all MemLoad in set I
        - Run findINS for each element to obtain each MemLoad corresponding set
      - 2] Setup a result set O
      - 3] Bucket each MemLoad in I at its SET level, ie the innermost REFERENCED level
        - Scan the LNT's Iter nodes from inner most to outer most
        - For a MemLoad p in I, its bucket is the FIRST scanned level whose Iter IS
          in p's INS, ValueEqual membership
          - Sets group CO-TRAVERSED loads: loads sharing their innermost referenced
            dimension land in the same set, ie the matmul gives {lhs, rhs} @ iterK
        - Record it and remove it from I
        - For all collected MemLoad at the same level, it forms a set and insert it into O
      - 4] O, contains all **different nested loop levels MemLoad set**
      - 5] Return O

    - (4) For each element in O, do final filtering
      - Setup a Candidative Set, denoted as CS
      - For each element S in O
        - If S's length < 2, skip
          - A singleton set = a load with NO co-traversed partner, ie a map that only
            modifies a single operand -> no reuse at all -> not worth caching
        - For all elements e in S
          - If e's tensor rank < Cache.dims, hardcoded 2 for now, ignore it
            - Ie any tensor with less than 2 dimensions is filtered out during
              candidate set formation, generalizes the ONLY 1 dimension access filter
          - Otherwise add it into CS
        - If CS contains more than Max.cs # of elements, exit loop
          - ie do not consider too many MemLoad to be replaced by cache

    - Cross-LNT loads (RULED 2026-10-21 — R4, v0 fail-closed)
      - A load whose INS spans >= 2 LNTs is NOT a v0 candidate: it gets
        an EXPLICIT non-candidate SiteDecision entry in the record
        (Promoted = false, reason "cross-LNT INS")
      - Never-bucketed loads (empty INS, no bucket) are likewise
        declared non-candidates with explicit record entries — never
        silently skipped
      - The UNION-of-assignments evaluation (judge such a load against
        the union of the referenced iters' assignments across LNTs) is
        FUTURE; foreign iters must NEVER be silently dropped from a
        candidate's INS to force single-tree ownership

  - Assignment means attach a **space of concurrency** to a specific iteration
  - Assuming we have LNT has K depth
  - Problem space formulation
    - For each dimension/loop, it has following possible assignment
      - 1) sequential
      - 2) CTA + WARP
      - 3) WARP
    - Notes, CTA assignment must be combined with WARP assignment also
      - WARP is used to decide how to work within that CTA sliced loop range in that dimension
    - Within each SoC, following properties must be provided
      - LoC: there's a attribute called **level of concurrency**/LoC
        - It decides what level of concurrency to be applied to that 
        - For example: iteration A is assigned with CTA + WARP
          - (1) decide the # of CTA maps to that dimension: denoted nCTA
          - (2) decide the # of WARP/THREAD maps to that dimension: denoted nWARP, and nWARP * 32 = nThreads
          - Notes each mapping # CANNOT be larger than a target allowed maximum one
        - Here is the conceptual loop to indicate what does those # mean

      - For a K depth loop nest tree
      - 1) For each loop iteration it will have up to 3 types of SoC choice
      - 2) Each SoC choice will also need to decide
         - (1) Level of Concurrency
          - Notes, for SEQUENTIAL, it must be 1
         - (2) tile_size
      - 3) For each such assignment, we call it a ParallelSchedule ie PSched
      - 4) For PSched, it must satisfy following constraints
        - (1) At least ONE CTA-assigned dim per LNT
          - Else the CUDA thread model cannot execute that LNT
        - (2) LoC concurrency bounds, the FINAL MODEL
          - Launch config: EXTERNAL, static at compile time
            - From the target GPU and green-context SM slicing
            - Defaults: Ampere, NO green context, 512 threads per CTA = 16 warps,
              CTA count rounded DOWN to the portion multiple (108 -> 100 CTAs)
            - Target-specific configs override the defaults, e.g. A6000 84 -> 80
          - Named portion constants, future adaptation points
            - PORTION_CTA = 10
            - PORTION_WARP = 8
          - Runtime hard pre-condition, ASSERT-AND-TRAP
            - Provided # of CTAs is a multiple of PORTION_CTA, ie 10
            - Threads per CTA is a multiple of PORTION_WARP warps, ie 8 warps,
              256 threads minimum
              - PORTION_WARP = 8 BECAUSE at the minimum config each portion is
                exactly one warp
          - Search window: at most K = 5 innermost dims SoC-assigned per LNT
            - Default scheduler config
          - Portion grammar
            - CTA-assigned dims' portions SUM to PORTION_CTA, ie 10
            - Warp-assigned dims' portions, CTA-coupled warp halves INCLUDED,
              SUM to PORTION_WARP, ie 8
            - The LAST assignment in each category may be -1 = derived remainder
              - The searcher decides the leading n-1, the last is the remainder
            - COUPLED-PORTION FLOOR (F2, ruled 2026-10-21): whenever the
              LNT carries a CTA dim, the independent WarpPortion must
              leave >= 1 warp portion for that CTA dim's coupled inside
              walk, ie WarpPortion <= PORTION_WARP - 1 in that case
              - Params.Validate and evalSchedule REJECT schedules that
                violate the floor — a zero-portion coupled walk emits a
                zero-stride inside loop, an infinite loop
              - "the coupled tile-inside walk implicitly consumes the
                remaining >= 1" is a CONSTRAINT, never an assumption
            - LoC of a dim = portion x quantum
              - quantum = total CTAs / 10 for CTA dims, total warps / 8 for warp dims
          - Sequential loops keep LoC = 1
          - EVERY LNT in the kernel is optimized under the SAME bounds
            - In v0 LNTs execute sequentially, each remaps the FULL launch,
              ie per-LNT exhaustion
            - Portion-sharding across LNTs is the FUTURE concurrent-LNT mechanism
            - The one dimensional CUDA mapping, gridDim.x = total # of CTAs and
              blockDim.x = # of threads per CTA, is a RUNTIME CONTRACT
              - It is how the per-LNT runtime map objects learn the totals they remap
              - It is NOT a compiler-side launch decision
        - (3) SMEM constraints
          - The Candidate Set generated by previous analysis pass forms **potential cache site**
          - For each cache, we ONLY allow the **LAST Cache.dims dimensions** of each MemLoad's tensor to be promoted as SMEM cache
            - Cache.dims, the dimension level reuse count, is a configurable parameter of this pass, hardcoded to 2 for now
              - Ie cache the last 2 dimensions of the tensor
            - For example: mem[a][b][...][x][y], we ONLY cache the last x/y 2 dimensions
          - A MemLoad will be promoted to SMEM/FRAG iff
            - 1) For a MemLoad, denote all its subscript access as list of [x0][x1][...][xn-1][xn]
            - 2) Judge Criterial — TIER RULE (amended 2026-10-21, R2:
              classify by the SoC of the site's COVERED dims, ie the
              cached trailing dimensions)
              - ANY covered dim CTA-assigned => cannot be promoted into CACHE
                - A CTA-covered tile has no coherent fill variant under
                  the v0 mechanics; the site is refused
                - Supersedes the former "all CTA assignment happens at
                  iteration <= xn-1 => SMEM" allowance — RETRACTED
              - Else ANY covered dim WARP-assigned => SMEM WINDOW
                - Cooperative LoadTileCta fill, window-sized buffer,
                  see the window-bytes model in 3)
              - Else, xn-1 and xn both sequential => ALL in FRAGs
                - Since xn-1 and xn access are in a single thread, hence using FRAGMENTS
              - NOTES (2026-10-24 tile-disable ruling): tile_size 1 no
                longer exists — every tile is >= 2 (the compiler never
                generates a non-tiling schedule), so the only demotion is
                the budget fallback's drop rule: a site whose halved
                covered dim would fall below the floor of 2 is DROPPED to
                GMEM (F4, floor amended 2026-10-24), never demoted to an
                un-tiled schedule
            - 3) For MemLoad that can be promoted to cache
              - WINDOW-BYTES feasibility model (amended 2026-10-21, R2 —
                rank-in-index => window-in-shape): SMEM bytes per site =
                element size x PRODUCT over the covered dims of
                - WARP dim d => #threads_d x tile_size_d, the whole
                  group's round window, NOT the single-thread chunk
                - SEQ dim    => tile_size_d
              - Since only the last Cache.dims dimensions are cached, 2 by default, each MemLoad uses tile_size_x * tile_size_y
                - each tile_size corresponds to given iteration
                - Per-dim size follows the window-bytes model above, a
                  WARP-covered dim contributes #threads_d x tile_size_d
              - It setups a constraints that SUMMATION of all cache size CANNOT be larger than SMEM size of SM on CUDA
                - Assuming as a known const as Max.cache (default 64 KB)
                - The sum is KERNEL-WIDE (R3, ruled 2026-10-21):
                  accumulated across ALL LNTs' promoted sites — decide's
                  feasibility, tiling-verify and tile-lower's budget
                  resolution all gate the SAME kernel-wide sum, never a
                  per-LNT one
              - FRAG sites are additionally bounded by MaxFragPerThread
                (F6, ruled 2026-10-21): SUM of per-thread FRAG bytes <=
                MaxFragPerThread, default 256 bytes/thread; it
                participates in the same halve/drop fallback as the
                SMEM budget

      - Objective Function: for a specific PSched, SINGLE-TERM
        - Maximize memory reuse = GMEM traffic avoided
          - traffic_avoided = SUM over cache sites of
            bytes_per_tile(site) * (reuse_count(site) - 1)
            - bytes_per_tile(site) = element size * product of the site's covered
              tile sizes, AFTER demotion per the Cache Tie Semantics
              - Per-dim sizes follow the window-bytes model (2026-10-21,
                R2): a WARP-covered dim contributes #threads_d x tile_size_d,
                a SEQ dim contributes tile_size_d
            - reuse_count(site) = PER-THREAD (amended 2026-10-21): # of
              times the cached bytes are re-traversed by the OWNING
              thread before reload = PRODUCT over the reuse dimensions,
              ie the tie level and the inner non-covered loop dims, of
              the OWNING thread's own trip count of that dim,
              ceil(extent_d / tile_d) for a sequential per-thread walk
              - Re-traversal by OTHER threads does NOT count toward a
                site's reuse — bytes loaded once and read once per
                thread avoid no traffic on the owning thread's behalf
              - PROMOTION GATE: a site with per-thread reuse < 2 is NOT
                promoted
              - Worked check (defaults): lhs reuse = its n-walk = 32 ->
                promoted; rhs reuse = per-thread m-count <= 1 ->
                declined, consistent with its 1 MB window exceeding the
                64 KB budget (intentional, loop_tile_lower.md §6bis
                PHASE 4)
          - Computed statically from the LNT plus the tie/tile decisions
          - NOTES: maximize traffic AVOIDED, NOT cache bytes
            - Footprint is bounded by the budget constraint, it is not an objective
        - The parallelism term is DELETED
          - Under mandatory full exhaustion total parallelism is CONSTANT by
            construction, so it carries no ranking signal
        - score = traffic_avoided
          - Larger is better

    - Algorithm to solve the above formentioned optimization problem
      - 1) Using a simple hardcoded search loop
        - NOTES, depth-limited search: the assignment search runs ONLY over the
          INNERMOST K consecutive loops of each LNT, K default 5
          - Every loop OUTSIDE the searched window defaults to SEQUENTIAL, LoC 1,
            no tile beyond trivial
          - 3 ^ K with K <= 5 is tractable for flat enumeration
        - 1] Setup a list of preset for each SoC types' LoC
          - A list of CTA LoC
          - A list of Warp LoC
        - 2] Setup a list of common searching size for **tile_size**
          - 32/64/128/256 etc ...
          - U can using # of potential cache to heuristically infer different sets to search tile_size
        - 3] Hardcoded loop for each iteration for SoC assignment
          - for (all loops in the innermost-K window of the loop nest)
            - for (all SoC types) // sequential, CTA, WARP/THREAD

        - Sample code

```

// for each permutation of thread x SoC type
// NOTE, only the INNERMOST K consecutive loops per LNT are searched, K default 5,
// all outer loops default to sequential, so 3 ^ K with K <= 5 is tractable
for (auto each_sched in psched) { // an incremental permutation iterator that dumps 3 ^ K solution space

  if (!is_feasiable(each_sched)) continue; // checking feasibility

  // calculating GMEM traffic avoided, ie memory reuse — the SINGLE objective term
  auto traffic_avoided = 0;
  for (auto cache_cand in candidate_set) {
    traffic_avoided += get_traffic_avoided(each_sched, cache_cand); // bytes_per_tile(site) * (reuse_count(site) - 1), computed statically from LNT + tie/tile decisions
  }

  // single-term score: the weighted multi-objective sum is deleted, parallelism
  // is constant under mandatory full exhaustion
  auto score = traffic_avoided;
  if (score > current_max_score) {
    current_max_score = score;
    current_sched = each_sched;
  }
}

- Composition Semantics, CTA x WARP
  - Warp allocations are PER-CTA
    - Every CTA holds the FULL thread space and re-partitions it
    - Warp ranks are CTA-RELATIVE, never global
  - The m x n cross product arises STRUCTURALLY
    - CTA ranks slice the CTA space, the m ranks m1/m2/m3/...
    - Within EACH CTA its warps slice the n space
    - Every CTA-sliced m rank gets a FULL n dimension space, partitioned by
      that CTA's warp group
    - Iteration unit is the THREAD
  - Two DISTINCT warp-level codegen forms
    - (a) independent WARP dim's between loop
      - Stride = #threads x tile_size, ie tile-chunk granularity
      - Each thread owns a WHOLE tile_size CHUNK of that dimension
      - Its inside loop is SEQUENTIAL over the chunk's elements
    - (b) CTA dim's coupled inside loop — the FLAT-INDEX FORM (ruled
      2026-10-23)
      - Stride = #threads at ELEMENT granularity
      - The IV's INIT is the NO-ARG flat thread query thread_map.index()
        (the absolute flattened 1-D rank); step = the coupled thread
        count; bound = the tile max. Index() = flatRank + i*#threads; the
        element address = round_base + Index(); the separate
        +index(threadDim) tuple add is DELETED (it supplied only the
        SLOWEST-axis coordinate — never a 0..#threads-1 element rank)
      - Each thread owns the tile rows/elements at its flat stride: threads
        with flatRank >= tile_max take ZERO trips (whole-body no-op) —
        single-owner EXACT while tile_size <= #threads
      - REGISTERED FUTURE WORK (do NOT implement): for tile_size >
        #threads a thread takes multiple trips and tid vs tid+coupled
        overlap — needs group-membership gating (is_first-style) when such
        tiles are ever searched
  - v0 default searcher POLICY, within the constraints, NOT a model rule
    - At most ONE CTA-assigned dim and at most ONE independent WARP dim per LNT
    - Same-category multi-dim composition, CTA+CTA or independent WARP+WARP,
      is FUTURE
      - Its combined-slicing arithmetic, product factors of the level's space
        and portions as the selection grammar, must be pinned BEFORE the
        searcher may emit such schedules

## Cache Mark and Loop Tile Rewrite

### Cache Mark

  - (1) For each MemLoad that are decided to be promoted to cache given the best schedule
  - (2) Refactory MemLoad to include a new field ctaCache
  - (3) Mark the MemLoad's ctaCache to be true for later mem insertion pass

### Loop Tiling Rewrite

- Rewrite the loop with the resolved **tile_size** per loop to standard loop structure
  - NOTES (2026-10-24 tile-disable ruling): every tile_size is >= 2 —
    loop tiling is never disabled

- Preparation of assignment result
  - After the above optimization, we need to run a **SoC numbering** pass
    - For **all LNT** in kernel

        - 1) For each Iter node, it must be assigned with a corresponding SoC object
        - 2) For each assigned SoC object

            - CTA: implicitly contains another coupled **WARP**
            - WARP

      - We need another pass to assign **dimension index** to each SoC belong to its own category
        - Decribed in Runtime Object Support
        - Each SoC object must be bounded to a dimension, ie 0/1/2/3/ ...
          - Same as (x/y/z) in threadIdx and blockIdx
      - For each LNT
        - For CTA and THREAD/WARP maintains 2 separate dimension index counter
        - Visiting LNT's Iter node in outer -> inner
        - For CTA, assign current CTA counter's value to this CTA SoC dimension, increase the counter
        - For WARP/Thread, same thing
      - After the numbering pass, each CTA and WARP/THREADs SoC object will have its designated dimension binding
      - The **dimension of SoC** is denoted as DoSoC
      - The per-LNT counters are correct BECAUSE the runtime maps are per-LNT scoped
        - Dimension indices are LNT-local, they are consumed by that LNT's
          IntrinsicGridMap/IntrinsicThreadMap nodes only
        - No cross-LNT collision: two LNTs both using CTA dimension 0 bind to
          DIFFERENT map object instances, they never alias

- Mechanical rewrite for tiling
  - Rewrite the loop to tile loop is straitforward
  - Notes we have already obtained the tile_size for each loop during the problem searching
    - HIGHLEVEL RULES to rewrite

        - Tile between loop => grid map level parallisation
        - Tile inside loop  => thread map level parallisation
      - (2) WARP/THREAD SoC

        - Tile inside loop  => sequential loop

          - Trip count is UNIFORM for every CTA/thread of the allocation, the
            CTA-uniform invariant holds by construction
          - NO map index in ANY induction variable, ranks appear only as
            in-body offset locals
        - In-body offset locals carry the rank
          - const auto d_offset = d_rank * T + d
          - d_rank is the CTA's/thread's rank in dimension d's allocation
          - CTA dims: rank from GridMapping, UNIFORM across the CTA's threads
          - WARP dims: rank from ThreadMap, PER-THREAD
        - ALL logic that depend on original loop before rewritting

          - Patch all InductionVariable node to use **Tile Insde Loop**
          - Also the index mathmatic changes, below shows how to calculate the global index
        - Parallel loop (CTA/THREAD)
          - Default use **strided style loop**, always safe to write and execute in cuda runtime
        - Ensure bounds check
          - Calculate actual tile inside loop's bound before entering into the loop
        - Tail guard
          - SATURATING bound form (F1, ruled 2026-10-21):
            off' = umin(offset, extent), tile_max = umin(T, extent - off')
            - Pure u32, wraps nowhere; tile_max == 0 exactly when out
              of range. The bare min(T, extent - offset) is WRONG in
              u32: extent - offset underflows toward 4e9 on tail rounds
              and the min picks T, so out-of-range ranks RUN instead
              of no-op'ing

            materialization, loop_tile_lower.md §4
