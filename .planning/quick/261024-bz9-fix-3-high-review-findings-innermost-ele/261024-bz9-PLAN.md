R-A (THE BRACKET LAW - the precise semantics for HI-01; implement THIS, not an abstract "innermost element" rule): For a reduced dimension K (rightmost of the input) decomposed into tile-between loop X and tile-inside loop Y: (1) reducer.Init() is placed in the OUTER loop of X - i.e. X's parent (loop X-1) - immediately BEFORE X, because the reduction spans the full iteration of X (all rounds). (2) reducer.Reduce() is INSIDE loop Y - it is a per-element operation and must go through all elements of Y per iteration (any other reduced-dim walks nest at this level too). (3) reducer.Combine() is placed in loop X-1, just RIGHT OUTSIDE loop X - immediately after X's body closes. Paired with Init. Output-element loops (for multi-dim outputs, e.g. out[i,j]=sum_k a[i,j,k]) wrap the bracket from OUTSIDE: the innermost output-element loop IS X's parent, so each output element gets Init -> X{...Y{Reduce}...} -> Combine -> gated store.
