## Locked design constraints (author rulings — preserve, do not re-litigate)

- Tiling is a factorization of the iteration polytope into M factor layers; within each layer a SoC (CTA / WARP GROUP / WARP / THREAD / SEQ) is assigned; parallelization is compiler-owned and every thread group is a whole number of physical warps.
- Code generation is mechanical, derived from the factor matrix (tile shape), LoC matrix, and stride matrix.
- Memory operations are mechanical: (a) memory subscripts rewrite when accesses hoist across a loop cluster; (b) global↔local coordinate mapping (parental↔subspace) formalizes subscript rewriting during cache insertion.
- Memory IR is three verbs (MemNew/MemLoad/MemStore) + storage class. A reducer is NOT an opaque runtime object: it lowers to a list of reduction operations moving the reduced value across the tiled SoC levels — fragment (sequential) -> SMEM region owned per thread / cross-thread collection -> SMEM region owned per warp / warp collection -> SMEM region owned per CTA / cross-warp collection -> (optionally) GMEM / cross-CTA.
- Loop nodes have no body; no control flow in v0; single-tier SSA.
- Where the source docs are genuinely ambiguous (two legitimate readings, needs an author decision), FLAG IT in an "Open Questions / Required Rulings" section of the canonical doc AND in the review doc. Do NOT silently pick one.
