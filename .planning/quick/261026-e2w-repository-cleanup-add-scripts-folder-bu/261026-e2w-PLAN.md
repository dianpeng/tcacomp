    2. **Why this design / motivation** — drawn from doc/tca.md §1 and doc/design.md: why another CUDA DSL compiler, what the compiler owns vs what the user never writes.
    3. **Architecture overview** — a text pipeline diagram from frontend source through lexer/parser/semacheck (internal/syntax), the pkg graph builder, the sea-of-nodes IR (internal/ir), the pass pipeline (internal/pipeline + internal/opt), codegen (internal/cg/cxx), to the emitted .cu + CMakeLists + runtime/ library. Include the exact three-window pass table with registry priorities read from internal/pipeline/pipeline.go (HIR 100-113, LOWER 114-950, TAIL memopt/const-dedup/dce).
    4. **IR design** — single-tier SSA node suite (no separate high/mid/low IR systems; lowering introduces LIR kinds into the same suite, HIR 20 kinds / LIR 13 kinds per doc/ir.md), sea-of-nodes Level-1 graph + scheduled AST-style CFG Level-2, unique integer node IDs, Input/ImpactBy operand convention with mutation choke points, effect model with the ONE end node, two-root-set DCE, and the per-pass verifier (invariants checked after every transformation pass).
    5. **Optimization passes — the specialized choices** (the README's emphasis; contrast with what common CUDA DSL compilers do, e.g. dedicated fusion passes / polyhedral models / user-annotated parallelism):
       - **Loop fusion via GVN**: fusion is not a dedicated pass — Iter nodes are side-effect free, so GVN value-numbering dedups identical loop headers/nests and fusion falls out for free (doc/optana/loop_fusion.md); memopt's store-to-load forwarding then cleans up what fusion makes redundant.
       - **LICM via scheduling**: no standalone LICM pass — the schedule pass (sea-of-nodes to AST CFG) places every node by scheduling number; invariant code (including cache fills) is hoisted as a *derived* consequence of scheduling, not a mandated placement (fill placement = dominated-by-operand-scope, re-derivable after any reshape; doc/optana/schedule.md).
       - **Loop tiling as combinatorial search**: the tiling decide pass formulates tile-shape/parallelization assignment as a discrete search over a traffic-avoided objective — explicitly NOT polyhedral (no data-dependence analysis needed; doc/optana/loop_tiling.md); SMEM/FRAG cache insertion by tile-lower (doc/optana/loop_tile_lower.md).
       - **Compiler-owned parallelization**: users never bind iterations to threads/blocks; every thread group is a whole number of physical warps; portions model (CTA/warp portion accounting).
       - **Structural race-freedom by construction**: one owner per address for structural stores, reduced dimensions only through reducers, in-kernel data flow through pipes, CTA-uniform collectives — enforced by the verifier after every pass, not by runtime sanitizers alone.
       - **Memory IR = three verbs + storage class**: MemNew/MemLoad/MemStore plus StorageClass; caches are compositions of the verbs; hardware-specific fusion (e.g. the mapping-driven cooperative loader call) happens only at codegen.
    6. **Code generation** (doc/cg.md): emitter architecture in internal/cg/cxx (deterministic on-the-fly SSA naming, fail-closed node whitelist), all memory access through the tca::rt view shim, one dynamic __shared__ pool with disjoint views, host launcher with the Tensor contract (dims derived from tensor occurrences, TCA_REQUIRE cross-validation, ValidateLaunch with queried — never hardcoded — smem ceilings), and the split: the compiler EMITS .cu + CMakeLists, it never drives nvcc (the user owns the build).
    7. **Runtime** (doc/rt.md): header-only INTERFACE CMake library (runtime/tca), dual-compile KernelInfo, portion-decomposition GridMapping/ThreadMapping, uniform iterator walk, bounds-predicated TensorView/SmemView/Frag, cooperative tile loaders LoadTileCta/LoadTileThread with runtime-owned synchronization, the reducers' scalar protocol; sm_86 ceiling is cp.async (no TMA).
    8. **Explicit storage tiers** — GMEM / SMEM / FRAG tiers and cooperative tiles, compiler-selected per tiling decision (weave into §5/§7 if it reads better there, but the tier model must be visible).
    9. **Getting started** — `scripts/build.sh`, `scripts/format.sh`, `tcacomp compile <input.tca>`, output shape (emitted .cu + CMakeLists linking tcacomp_runtime), and the e2e gate `TCACOMP_E2E=1` for GPU tests (unit runs stay hermetic).
    10. **Repository layout** — table mapping cmd/, pkg/, each internal/ package, runtime/, doc/ to one-line responsibilities.
