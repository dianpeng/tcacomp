<objective>
Fix the schedule pass per the 261021-ta3 code review (REVIEW.md findings CR-01/CR-02, HI-01/HI-02, ME-01..ME-03, LO-01/LO-03/LO-04), under the user's locked decisions plus the mid-planning refinement: the effect chain (ImpactBy) is treated IDENTICALLY to use-def/input edges throughout the scheduling model.

Purpose: the current containment clamp is provably wrong in-pipeline (multi-round SMEM fills hoisted to the prologue → stale windows → wrong numerics once final_lower consumes the AST) and as a class (unenclosed consumers of in-loop values — reduction shapes, post-nest stores, every kernel's end node — execute BEFORE their dependencies, pinned as intended by existing tests).

Output: a sound placement model (uniform effect-chain containment + two-case placement, no clamping), a fail-closed cross-block ordering net, fail-closed guards, updated pins, and a committed full-pipeline integration test converted from the review's scratch probe.

Design rulings baked into the tasks (refining locked decisions 1a/1b; nothing reversed):

1. UNIFORM RELATION. Propagation already maxes over DataDeps AND EffectDeps — keep it, and cite it as the design intent. Containment cap AND ownership become uniform too: a node's containing loop is the deepest loop whose body reaches it through the data + impact-PREDECESSOR closure — the exact relation tiling's reachableFrom uses (lower_cache.go:498). That is what makes the fill's cap 3: it is an impact-predecessor of the in-body buffer access.
2. TWO-CASE PLACEMENT, NO CLAMP. For each live unanchored node with final SN(n) and uniform cap capUni(n):
   - SN(n) <= capUni(n) → place AT SN(n) (earliest legal point; SN 0 = first prologue, LICM intact; e.g. the fill's src load lands at SN 1 = per-M-round, the buffer MemNewSMem at SN 0).
   - SN(n) > capUni(n) → place AFTER the loop(s) that produced the uncontainable SN: the epilogue Group of the contributing nest; multi-LNT consumers land in the LAST contributing cluster in cluster order. The kernel end node thereby lands in the last LNT's epilogue.
3. WHY NO SPECIAL CASES ARE NEEDED. Tile-lower ALREADY encodes inside-vs-after on the edge TARGET: repointChains points post-nest consumers at the nest ROOT node because "the ForLoop node as effect-def" denotes whole-loop completion (lower_rewrite.go:517-544 comment). Real tile-lower output needs no special cases; the epilogue case falls out of the uniform rule. Hand-built fixtures with un-repointed in-body effect-defs (the review's hazard probes) also land correctly: SN 1 > cap 0 → epilogue.
4. The cross-block ordering net (locked decision 2) stays exactly as specified — it is the empirical guard for this rule.
5. HI-02 refinement (necessary for correctness, documented in-code): the effectful no-hoist floor applies to memory-ACCESS kinds (loads/stores) but NOT to allocation kinds (KindMemNew, KindMemNewSMem, KindFragNew). Allocations are shared declarations consumed at multiple depths (the buffer is an operand of the shallow fill AND of deep accesses) — flooring the buffer at its deepest accessor would put it after the fill and fire the net. Hoisting a declaration is semantics-preserving; the pin is buffer at SN 0.
6. SN SEMANTICS (extends D-03). Persistence stays as ruled (Base.schedSN + Base.schedBlock, written together via SetSched, never printed/serialized/verified). But under the two-case rule SchedSN keeps the propagated DEPTH REQUIREMENT even when the node lands in an epilogue (SN=r, block=epilogue Group): SN and block are COMPLEMENTARY — requirement vs landing zone — not redundant. final_lower's reducer rule ("using Reducer's own SN ... OR using reducer's first operand") works via both routes: the Reduce lands in its nest's epilogue with SN = the reduced loop's depth; its operand's SchedBlock IS the loop block. Epilogue nodes therefore keep their propagated SN at stamping time (NOT an after-nest rank).
7. NEST IDENTITY ON GROUPS (API gap to close, option (a)). Epilogue and prologue Groups need nest identity so final_lower can map an epilogue-landed node back to its owning nest: an unexported nest field on ASTBlock plus an exported Nest() *ASTLNT accessor (O(1), explicit), set during cluster construction via a new exported constructor; Groups outside any cluster (the kernel-body Group, the no-loop case) carry nil. Loop blocks keep Loop() as their nest identity. ASTKernel.LNTs becomes []*ASTLNT so blocks can point at stable LNT records (the schedule pass is the sole producer).
</objective>
