LOCKED DESIGN RULINGS (doc/optana/final_lower.md as amended + review
addendum §10 round 2 — verdict GO; implementing anything else is a bug):

- LR-1: Placement law. X = the OUTERMOST loop over the reduced dim (the
  tile-BETWEEN loop on the tiled path; the single loop when T==1). Init
  immediately BEFORE X and Combine immediately AFTER X, both in X's parental
  block body (when X is the cluster-outermost loop, that block IS the owning
  LNT's prologue Group). The Reduce method call stays INSIDE the home loop
  (tile-inside; the single loop at T==1). Init/Combine never bracket only a
  tile — no per-tile partials (doc/tca.md §5.10).
- LR-2: @r identification. Reduce Input #0 → producing Map → ir.AsOf → the
  LAST dim operand of the As order. Chase through reduce-after-reduce chains
  (Input #0 of a Reduce may be another Reduce — recurse). NO Map/As chain is
  a HARD diagnostic, never a guess. Runs BEFORE Map Lower (which rewires
  Input #0 away).
- LR-3: Construction carries ALL state: RuntimeXXXReducer(%init, %lambda) —
  init unwrapped from the Reduce's KeyedAttribute("init"), lambda = SSAUse to
  the Reduce's trailing lambda node. Init() is ARGUMENT-FREE. The (prev, cur)
  combiner application is RUNTIME-INTERNAL: the compiler emits NO lambda-call
  node, and NEVER emits current_value/init_value reads. prev is the runtime's
  member field; the lambda's formals are the carriers.
- LR-4: Node taxonomy. Dedicated construction nodes (no generic
  RuntimeConstruct): RuntimeKernelInfo(), RuntimeGridMapping(%kernel_info,
  ndim, portions...), RuntimeThreadMapping(same shape),
  RuntimeSequentialReducer/RuntimeWarpReducer/RuntimeGlobalReducer(%init,
  %lambda). Exactly TWO generic nodes: RuntimeCallMethod (input #0 = the
  object, #1..K = args; string PAYLOAD method ∈ {Init, Reduce, Combine};
  ordered side effect — never pure, never GVN-CSE'd) and RuntimeGetAttribute
  (input #0 = the object, #1..K = attribute args; string PAYLOAD attribute ∈
  {total_cta, total_thread_per_cta, index, dimension}; pure read, GVN-sound).
  Names are string payloads (intrinsicNode.field precedent), NEVER operands.
- LR-5: Families: NEW FamilyRuntime = KernelInfo/GridMapping/ThreadMapping
  constructions + RuntimeCallMethod + RuntimeGetAttribute. FamilyCollective
  gets its first members: the three reducer constructions (its reserved
  slot). All new kinds are LIR tier, appended before KindEnd (append-only
  rule, no KindVersion bump). RuntimeGlobalReducer is v0-unreachable forward
  scaffolding (tca.md §5.10: no CTA-parallel reduced dims in v0) — registered,
  never emitted by the Soc rule on reachable inputs.
- LR-6: Naming. The "Intrinsic" vocabulary is renamed to Runtime throughout:
  the pre-final-lower query kinds (today KindIntrinsicGridMap/ThreadMap) are
  renamed and after final-lower vanish from every graph.
- LR-7: Specialization follows X's Soc (ASTLoopMeta / provenance entry):
  0 (seq) → RuntimeSequentialReducer, 2 (thr) → RuntimeWarpReducer, 1 (cta)
  → RuntimeGlobalReducer.
- LR-8: T = element type of the Reduce's Input #0 (the piped value);
  homogeneity vs the init attribute's type per doc/tca.md §4.2 is CHECKED at
  lowering, fail-closed. KindLambda stays deliberately untyped.
- LR-9: Map Lower runs AFTER Reducer Lower. Per eliminated Map: (1) RAUW the
  Map node to its body expression (the trailing lambda node's body operand);
  (2) EXPLICITLY erase the trailing As operand; (3) dispose of the orphaned
  lambda node per LR-10.
- LR-11: Runtime objects. KernelInfo prepended as the FIRST item of the
  kernel Body Group (the Prototype block is signature scope — untouched).
  Per LNT (one pair, ALWAYS): RuntimeGridMapping + RuntimeThreadMapping
  prepended to the OWNING LNT's prologue Group — never the kernel's first
  Group.
- LR-12: Query rewrite. Every launch-map query node is rewritten to
  RuntimeGetAttribute(%<owning LNT's mapping object>, field, dosoc): the
  query's SchedBlock → owning nest → that LNT's construction; grid queries →
  the GridMapping, thread queries → the ThreadMapping. After the rewrite the
  query kinds vanish (pre-final-lower material only).
- LR-13: Accumulator tiles. When non-reduced loops run between X and the
  home loop, the reducer state is a TILE of accumulators: the Reduce call
  carries the slot index — RuntimeCallMethod(%reducer, "Reduce",
  betweenLoopIVs..., %piped) — while Init/Combine stay argument-free and
  cover the whole tile (doc/tca.md §5.10 point 3).
- LR-14: Fused consumers. Consumers of Combine()'s result are placed after
  Combine, INSIDE a RE-ITERATION of the non-reduced inner loops (the loops
  strictly between X and the home loop in the AST nesting), as fresh
  sequential ForLoop blocks over the same dims/bounds; consumer references
  to those loops' dimvars are RAUW'd onto the re-iteration loops' dimvars
  (doc/tca.md §5.10 point 4).
- LR-15: Launch configuration (gridDim/blockDim) is a CODEGEN contract item
  (tiling Params → kernel metadata → host launcher + runtime validation),
  NOT an IR node — final-lower emits nothing for it.
