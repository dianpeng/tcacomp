<author_ruling name="flat-index() ruling (2026-10-23 — LOCKED, resolves the open rank-formula decision)">
- index(<dim#>) returns the per-dimension tuple coordinate — EXISTING
  behavior, unchanged.
- NEW: index() with NO argument returns the thread's absolute FLATTENED 1-D
  index in the CTA (ThreadMapping; GridMapping's no-arg form is the
  blockIdx.x analog). lane id / warp index derive from it
  (index() % 32, index() / 32). The compiler NEVER inlines threadIdx.x
  itself — the maps stay the opaque seam.
- Coupled-inside walk (C1): the CTA dim's tile-inside walk becomes a thread
  iterator with init = the flat index() query, step = coupledThreads,
  bound = tileMax; the element address = roundBase + Index()
  (Index() = flatRank + i*coupledThreads); the separate +index(threadDim)
  add is DELETED. Threads with flatRank >= tileMax take zero trips
  (whole-body no-op); with tile <= 64 < coupledThreads=256 the upper thread
  half (256..511) takes zero trips and ownership is single-owner exact on
  both goldens.
- REGISTER as future work (do NOT implement): for T > coupledThreads a
  thread takes multiple trips and tid vs tid+coupledThreads overlap — needs
  group-membership gating (is_first-style) when such tiles are ever
  searched.
- C2 store ownership: PLANNER PICKS the mirrored walk — the epilogue
  re-iteration reuses the SAME thread-parallel coupled-walk form (flat init,
  coupled step, tileMax bound), so each out row is stored by exactly its
  owning thread; branch-free (Has() is the walk guard); replicated-idempotent
  stores are the documented fallback ONLY if the mirrored form is proven
  structurally infeasible (executor documents the deviation).
</author_ruling>
