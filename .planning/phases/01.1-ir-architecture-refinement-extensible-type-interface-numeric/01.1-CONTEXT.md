# Phase 01.1 Context: IR Architecture Refinement

## Why This Phase Exists

User review of the Phase-01 IR core identified four architectural
weaknesses that will block near-term evolution (new workload types,
optimization passes, frontend landing). The IR is the foundation of all
optimization — it must be flexible enough to accept future evolution
without another rewrite.

## The Four Directives (verbatim intent)

### 1. Type system must be extensible

> The type definition in ir/ module is too inflexible. For now it is
> really a tensor/scalar type, it cannot be extended to support other
> types, like tuple/struct etc ... The new types are gonna landed very
> soon since we will extend the IR to support more workload.

Design direction (user-specified):
- Rename the current concrete type to **`NumericType`**.
- Declare **`Type` as an interface**.
- Subclass all different type components (numeric now; tuple/struct/etc.
  later); consumers type-assert to the concrete component whenever they
  need to access sub-typed details.
- Must remain interned / identity-compared where the current code relies
  on pointer equality (map keys, deterministic emission) — decide how
  interning survives the interface transition.

### 2. Clear SSA/Value design (SSAUse / SSADef / SSAVar)

> Normally the statement in frontend code is typically like lhs = rhs.
> Lhs is optional. We define rhs part as interface Value, ie every
> statement that can generate Value, a none Value is a Value but just
> nothing. The LHS, if shows up, is a SSADef, which represents a single
> SSA name, ie immutable, referential transparent. For all operands
> reference inside of the RHS, it is a **SSAUse**, which represents a
> USE to a SSA variable. SSAUse and SSADef underlying ALL POINTS to a
> SSAVar object, which is the actual object that stores the
> relationship of use-def/def-use. Notes, SSAUse and SSADef are just
> pointer wrappers, it is value type, can be safely copied everywhere.
> To allow reverse operation, ie mutation from SSAUse/Def but propagates
> to all SSAXXX object, to mutate any part, just modify SSAUse and
> SSADef pointed part inside of the SSAVar object.

Reference implementation: `/home/ps/Workspace/cuda/project/seabird/internal/cfg/ssa_var.go`
(design reference, NOT a dependency — different module, read-only).

Key mechanics from the reference:
- `SSAVar` is the sole pointee: holds id, name, the defining Value, and
  the list of reference-pointer records.
- `SSADef{ssa *SSAVar}` / `SSAUse{ptr *refRecord}` are value-type handles;
  copies share the underlying record, so a mutation through any copy
  propagates to all of them.
- Ref records are indirect (pointer-to-pointer): rewiring a use sets
  `record.ssa = newVar` — every copy of that SSAUse sees the new target.
  Whole-chain moves (`ReplaceAllReference`) relocate every live record
  into the new var's list in one pass.
- Invalid/zombie states are representable but checkable (`IsKilled`,
  nil-safe accessors) so the verifier can flag them structurally.

Design goals the user stated for the mutation model:
- Mutate safely and simply.
- Mutations **enforce graph invariants by construction** — "u cannot
  express invalid mutation of the graph". The choke-point discipline
  (all chain edits through one API, IR-04) stays; the API surface
  becomes the handle-based SSAUse/SSADef operations.

### 3. Visitor-pattern graph walk with early bailout

> The walk function of IR graph is too trivial also, better use a
> Visitor pattern to allow fine grained visiting of the IR graph. And
> also allows early bailout/exit of the walk/visit based on return
> value.

Design direction: replace/augment `ir.Visit(g, func(Node))` with a
Visitor interface (or callback returning a control value) supporting:
- fine-grained per-node visitation (pre-order at minimum; consider
  enter/exit hooks for subtree scoping),
- early termination / pruning of subtrees based on the visitor's return
  value (continue / descend / stop),
- deterministic order preserved exactly (BB statement order, operand
  order, lambda bodies — emission and verification depend on it).

### 4. General polish — interface + subclass style throughout

> IR is the fundation of all optimization, please in general polish its
> usage and design. Notes, the IR needs to evolve a lot and it must be
> flexible enough to accept all sorts of future evoluation. Hence better
> use interface + subclass style design pattern to fully allow
> flexibility.

- Node families stay interface-based (`Node` root, family interfaces,
  unexported concrete structs per kind — go/ast shape), but re-audit the
  surface: anything that hard-codes the current kind set or the current
  Value==Node identity must become extensible.
- Prefer small, focused interfaces over wide ones; concrete assertion at
  use sites (per directive 1's pattern).

## Hard Constraints (carried from Phase 01 — do NOT regress)

- **Goldens byte-identical**: `pkg/testdata/matmul_scale.ir` (doc-pinned
  §5.1 oracle) and `internal/visualization/testdata/matmul_scale.dot`
  must still pass byte-exact after the refactor. The printer's canonical
  output format is unchanged.
- **Stdlib-only**: `go list -m all | wc -l` == 1; pure Go stdlib.
- **Correctness model**: race-freedom by construction; the post-pass
  verifier checks chain consistency both directions (use-def + def-use)
  with diagnostics naming node ID, last-touched-by, and invariant.
- **Determinism**: BB statement order + operand order only; maps are
  lookup-only, never iterated for output (VER-08 byte-compare gates).
- **Single-tier IR**: no separate high/mid/low IRs; lowering adds kinds
  to the same suite; Kind enum stays versioned/append-only.
- **No panics in library code** (pkg/ and ir/ never panic; errors are
  returned eagerly or via the verifier).
- **One BB per kernel in v0**; no phis; CFG extension comes later.
- **Mutable-with-use-lists is sanctioned** (CLAUDE.md decision b) — the
  SSA redesign replaces the *Use intrusive-record mechanics with the
  SSAVar ref-record mechanics; the mutable-graph philosophy itself is
  unchanged.
- **Stable integer node IDs** from Graph.NewID only; Erase tombstones,
  never reuses (IR-05).
- **LastTouchedBy stamping** at every choke-point mutation (D-17).
- **TDD**: RED test commits precede implementation commits; only
  fundamental tests (per design.md, no excessive suites).

## Open Design Decisions (planner to resolve, with rationale)

1. **Interning under the Type interface**: keep a package-level intern
   table keyed by a content-hash of concrete descriptors, returning the
   `Type` interface; `NumericType` carries `ElemType` + `[]DimRef`.
   Equality: pointer identity for interned numerics + an `Equal(Type)`
   method on the interface for cross-component comparison. Must keep
   determinism (no iteration of intern maps for output).
2. **Statement/Value split**: `Value` becomes a real interface
   (RHS-capable nodes implement it); a `NoneValue` representation
   satisfies "a none Value is a Value but just nothing". Which kinds
   produce Value vs NoneValue (store/return = NoneValue?) — decide and
   document. Keep `Node` as the universal root.
3. **SSAVar ownership**: per-node SSAVar (as now, one per def-producing
   node) vs per-statement. The current graph has statement-level
   numbering (`statement #N`) and node-level IDs; the redesign should
   preserve the golden numbering behavior exactly.
4. **Back-compat vs clean break inside internal/ir**: external golden
   bytes must not change, but internal APIs may break freely (all
   consumers are in-repo). Prefer the clean target design over
   compat shims; update all call sites.
5. **Visitor shape**: `Visitor` interface with `Visit(Node) VisitResult`
   (enum: Descend/SkipChildren/Stop) vs func callback returning a
   control enum. Downgrade/upgrade path for `ir.Visit` users (pass
   legality, future passes). Keep an iterative walk (cyclic-graph safe).
6. **MutContext API over handles**: map the five choke points onto
   handle operations (e.g. `use.Replace(def)`, `def.ReplaceAllUsesWith`,
   SSAVar-level rewiring) while keeping LastTouchedBy stamping and the
   fail-closed verifier (surplus-operand check, WR-01, stays).

## Success Criteria (phase goal-backward)

1. `Type` is an interface; `NumericType` implements the current
   tensor/scalar semantics; a consumer can type-assert to `*NumericType`
   for elem/dims; the interning + determinism guarantees hold; tuple/
   struct can be added later as new implementations without touching
   NumericType or the printer's numeric paths.
2. SSA model: `Value` (interface, incl. NoneValue), `SSADef`,
   `SSAUse` — all value-type handles over a shared `SSAVar` pointee;
   mutations through any handle propagate; invariants enforced by the
   choke-point API; verifier still catches corruption both directions
   with the same diagnostic richness.
3. Visitor walk: fine-grained visitation with early bailout; all
   existing deterministic walks (verify, print, dot, legality) migrate
   to it; cyclic graphs still cannot overflow the stack.
4. Whole suite green; goldens byte-identical; `go vet` clean; stdlib-only
   module count == 1; determinism byte-compare tests pass.
